# Firmware

C11, no vendor HAL, no dynamic allocation. Everything below `src/` builds
for the host and for a Cortex-M4F; only the HAL callbacks differ.

| File | Role |
|---|---|
| [include/hal_spi.h](include/hal_spi.h) | The whole hardware boundary: one SPI transaction, the DOUT/RDY line, a delay, the input and gain selectors |
| [src/adc_spi.c](src/adc_spi.c) | AD7124-8 class driver: reset, ID probe, configuration with read back, data with appended status |
| [src/sampling_engine.c](src/sampling_engine.c) | DOUT/RDY interrupt to a lock free single producer, single consumer ring; numbered samples; overflow and error counters |
| [src/calibration.c](src/calibration.c) | Two point calibration in integer arithmetic, CRC protected coefficient records |
| [src/host_link.c](src/host_link.c) | Framing for the host link, CRC-16 |
| [src/daq_app.c](src/daq_app.c) | Bring-up, the calibration sequence, streaming |
| [host/mock_ad7124.c](host/mock_ad7124.c) | The converter on a mocked SPI bus, written independently of the driver, with fault injection |
| [host/daq_sim.c](host/daq_sim.c) | Firmware in the loop: the application against the mock, fed by the behavioural converter model |
| [test/](test) | Unit tests; `fixtures/cal_vectors.h` is generated by the Python reference implementation |

```bash
make test    # unit tests with address and undefined behaviour sanitisers
```

```bash
make arm     # compile for Cortex-M4F, needs arm-none-eabi-gcc and newlib
```

Not written yet: the STM32 board support (SPI peripheral, EXTI on DOUT/RDY,
GPIO, UART or USB), startup code and a linker script. See
